How I Approach SOP & Process Documentation

From business knowledge to usable documentation
01 — DISCOVER

Understand the business

Review existing SOPs, policies and process material and work with subject-matter experts to understand how the work is actually performed.

02 — MAP

Map the process

Capture roles, systems, inputs, outputs, decisions, controls, approvals, dependencies and exceptions from beginning to end.

03 — DOCUMENT

Write the SOP

Convert the validated process into concise, standardised, step-by-step instructions that users can follow without guesswork.

04 — VISUALISE

Create the process visual

Develop matching flowcharts or swimlane diagrams showing the same roles, activities, decisions and exceptions as the written procedure.

05 — CONNECT

Build the library

Apply document IDs, naming conventions, version control, cross-references and a structured, hyperlinked document index.

06 — VALIDATE

Quality-check the system

Cross-check the SOP and visual one-to-one, validate the process with stakeholders and ensure exceptions and control points are represented.

The objective: create documentation that answers the questions a user needs answered at the point of work — What happens next? Who does it? Which system is used? What controls apply? And what happens when the normal process changes?
